# 如影随形 · 战斗反馈日志 1.2.0

这是独立的《饥荒联机版》客户端模组，用于给如影随形项目提供可复查的战斗反馈。无需服务器安装或管理员权限。

死亡反馈分为已确认观测、关联线索和未知项。每次净掉血记录同步原因、前后0.35秒内同关卡的受击通知、实际携带的攻击者及环境线索；时间关联不等于确定归因。附近攻击动画、地刺、孢子和炮弹只列作现场线索。报告增加护甲变为空槽的时间及此前耐久、最后6秒净掉血、手持物变化、角斗场阶段、人物配置跑速和平台。配置跑速可能未同步，不能代替服务器实测移速；死亡后的自动卸装不作为护甲耗尽证据。

## 使用

1. 将整个 `shadow_combat_diary` 文件夹放入游戏 `mods`，在游戏的客户端模组列表启用“如影随形 · 战斗反馈日志”。
2. 进入世界自动记录。右上角“战斗日志”可暂停/继续；“反馈：写入日志”重新输出最近死亡反馈。尚无死亡时输出当前检查点。
3. 每次死亡自动生成中文总结和 JSON 回放；复活后自动开始新生命统计。默认每 0.25 秒采样，保存最近 30 秒。普通受击、生命变化即时写日志，不必等死亡。
4. 退出游戏前后都可导出。PowerShell 中执行（把路径改成实际安装位置）：

```powershell
& "E:\STEAM\steamapps\common\Don't Starve Together\mods\shadow_combat_diary\tools\Export-CombatReports.ps1"
```

默认在桌面生成“战斗反馈”：`反馈汇总.md`、逐次死亡 `.md`/`.json`、`combat-events.jsonl`。把这些文件发给合伙人即可；工具不会自动发送。

导出旧日志或另存位置：

```powershell
& ".\tools\Export-CombatReports.ps1" -LogPath "C:\完整路径\client_log.txt" -OutputDirectory "C:\完整路径\本次反馈"
```

游戏重启可能轮换 `client_log.txt`，建议每轮测试结束就导出。最新一份死亡 JSON 另通过游戏原生持久化 API 保存在键 `shadow_combat_diary_latest`；它只保留最近一次，不能替代每轮导出。可在本地控制台重新打印：

```lua
TheSim:GetPersistentString("shadow_combat_diary_latest",function(ok,s) if ok then print("[SCD] "..require("json").encode({schema=1,kind="death_report",report=require("json").decode(s)})) end end)
```

## 自动关卡识别

读取当前项目 0.13.3 的 `control.jobs.arena.adapter.hud`，或已经加载的 ASTRA `mode_hud_client`。只读取参与者自己的关卡、路线、副本编号及代次，不调用开局、准备或控制请求。HUD 在死亡时消失会短暂保留最近 10 秒的关卡并标记来源及信息年龄；超过时限明确显示未识别，不猜关卡。

未接入关卡协议的服务器，可用本地控制台手动标记：

```lua
SHADOW_COMBAT_DIARY:MarkStage("第8关 帝王蟹 / 自定义测试")
SHADOW_COMBAT_DIARY:Note("开始测试融冰撤离")
SHADOW_COMBAT_DIARY:MarkStage(nil) -- 清除手动标记，恢复自动识别
SHADOW_COMBAT_DIARY:Export()
```

## 报告内容与边界

- 受击通知的本机日期、游戏模拟时间、本次生命/本关已进行秒数；生命下降、恢复分开统计。
- 死亡关卡/路线、装备及可用耐久、目标/附近敌人的位置距离、可识别动作和帧、延迟、接管状态、三维、季节和夜晚状态。
- 死亡前 30 秒采样与事件、中文反馈建议。同一死亡多种信号只生成一份报告，复活后重新计数。
- 受击通知和生命下降不一一对应：格挡可能只通知不掉血，环境伤害可能掉血却无攻击者；同帧同步可能合并。普通远程客户端不提供准确攻击者/伤害时保留未知，附近敌人只是候选。最大生命变化重设基准，不伪算成伤害。
- 时间是客户端接收/采样时间，不是服务端精确命中时间。建议是排查方向，不能自动证明代码根因或某怪负责伤害。
- 回放最多约 30 秒、附近敌人最多 12 个，事件缓冲 500 条、关卡明细 64 段；生命累计计数不受关卡明细上限影响。高于采样频率的瞬时动作可能不可见。
- 不修改走位、装备或伤害，不替换 RPC/战斗函数，不读取聊天、账号和连接地址，不自动向任何人发送日志。可与旧的战斗诊断模组同时启用。

## 验证

提供离线回归，覆盖客户端事件顺序、重复信号、复活、关卡切换、最大生命改变、持久化回调与导出。离线模拟通过不等同于真实服务器兼容性通过；游戏启用后的首轮实测仍需核对实际日志。


## 1.1.0 自动协作兼容

长JSON会以每段不超过日志打印上限的 record_chunk 分段输出，使用 hex-adler32-v1 编码及完整性校验。随附导出工具与测试端Relay可重组；缺段或校验失败不会冒充完整报告。原来的schema=1、session、逻辑seq和报告ID保留。

报告新增 test_build，默认 unverified。只有测试端核对安装清单、写入 scripts/scd_test_build.lua 且本轮实际加载的项目目录及版本一致时才附带验证过的SHA/build_id。存在两份启用的Shadow或版本不匹配会保持未验证。Relay的新报告上传必须通过这个门槛，不能把当前Git HEAD当作历史报告版本。
