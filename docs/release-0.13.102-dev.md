# 0.13.102-dev：Mod 动作发送限频

在本 Mod 的控制动作、迁入的原生走 A/走位入口和旧 ActionLibrary 中共享同一玩家的动作限频。没有覆盖游戏的全局 SendRPCToServer；玩家手动操作与其他 Mod 不经这个限频器。

| 动作 | 最短发送间隔 | 同一请求重复间隔 |
| --- | --- | --- |
| 移动目标 | 100ms | 落点相差不足0.25码时250ms |
| 攻击 | 150ms | 150ms |
| 背包/装备动作 | 100ms | 同动作同物品400ms |
| 场景交互 | 100ms | 同动作同目标250ms |
| 停止 | 新动作后的首次取消立即发 | 无新动作时200ms一组 |

这里限制的是动作请求，一次动作可能包含多条原版 RPC，例如普通预测移动、停止、批量转移。没有声明全 Mod 的所有网络包总数必定低于10/秒。限频在发起动作之前执行，必要的协议组完整发送；不把限频返回当作已完成，不排队重放过期目标。原流程下一轮重新检查状态后再尝试。

直接场景动作、地面动作、补燃料及原生攻击的预演回调增加一次性发送保护。换装遇到“请求限频”视为暂时等待，不加入装备失败黑名单。停止仍立即清理本地动作与控制；新动作后的首次停止不被旧停止窗口阻挡，但停止不会清除移动的最短间隔而形成绕过。

修改文件：scripts/shadowself/control/rpc_throttle.lua（新增）、control/actions.lua、native/engine/HitAndRun.lua、legacy/action_library.lua、legacy/combat_equipment.lua，以及modinfo.lua和queendebug.lua的版本号。

离线验证：全部Lua通过5.1解析。124个套件，123通过；arena_lifecycle仍为已知的服务器关卡配置快照差异，未隐藏。新套件 tests/rpc_throttle102.lua 以60Hz调用真实发送封装并统计模拟网络请求：

- 两秒持续改变普通移动目标：120次调用，仅20次RPC发送。
- 两秒重复相同移动落点：120次调用，仅8次RPC发送。
- 两秒重复攻击：120次调用，仅14次RPC发送；迁入原生攻击入口同样通过。
- 重复停止保留完整4包取消协议；新动作可以立即取消，不能通过Stop重置移动额度。
- 预演回调重复触发只发一次；撤销的动作不发送。
- 批量转移整组准入，预测移动开始/结束协议完整。

若干旧测试原先在同一模拟时刻连续验证多个独立动作，现补充了动作间的模拟时间，继续比较准入后的原版协议参数和装备确认。新测试单独覆盖窗口内拒绝及窗口外恢复，未对测试关闭限频。

本轮未进行服务器实战。安装后需重载Mod/重进游戏，重点观察紧急躲避、停手后再攻击和连续换装的响应。没有修改关卡战术配置，也没有提交或推送GitHub。
